## 〇、分享与部署（含 AI 小白鹭怎么才能用）

先说结论，再说两条路。

### 0.1 三种分享方式的效果差别

| 方式 | 网站本体 | AI 小白鹭 |
|---|---|---|
| ① 把 `康鹭记忆-终版` 文件夹压缩后发给别人（对方解压双击 `index.html`） | ✅ 全部正常 | ⚠️ 只走「站内检索模式」，**不接大模型** |
| ② 部署成公网网址（GitHub Pages），发链接 | ✅ 全部正常 | ✅ 正常（前提：Worker 里的 Key 有效） |
| ③ 本机演示（自己双击打开，项目根目录放 `_ai-config.local.js`） | ✅ | ✅ 直连 DeepSeek（Key 在自己机器上） |

**为什么 ① 的 AI 只能检索**：`file://` 打开的页面没有域名，
而 `ai.js` 里那把 Key 只从 `../_ai-config.local.js` 读 —— 这个文件**故意不进交付包**
（里面有明文 Key），所以对方机器上没有它；而 `proxyUrl` 在交付版里是空的。
两条路都没有 → 自动降级为站内检索，并在回答末尾如实标注「站内检索模式」。

> 想连 AI 就必须有一个**公网地址**：Worker 代理地址（`proxyUrl`）或站点自己的域名。
> 只发文件、不部署，AI 就不可能接上大模型 —— 这不是 bug，是安全设计。

### 0.2 两条铁律

1. **密钥绝不进前端、绝不进交付包。** `_ai-config.local.js` 放在**项目根目录**
   （即 `人文数字-网站\` 下，与 `康鹭记忆-终版\` 平级），
   这样"把终版文件夹整个发给别人"不会连密钥一起发出去。
   `_pack-final.js` 现在有两道防线：跳过所有 `_` 前缀文件、并全文扫描交付目录里的
   `sk-` 字符串，发现即中止打包。
   **踩过的坑**：`ai-config.local.js` 原先就躺在交付目录里，被整包发出去了；
   更糟的是一次打包中途失败留下 `_stage2`，下次打包把残留的 `_stage2` 又递归拷了进去，
   于是"已经删掉的密钥"又回到压缩包里 —— 所以 `cp()` 必须连 `_` 前缀的**目录**一起跳过。
2. **`proxyUrl` 在交付版里必须留空。** `ai.js` 的优先级是
   「有 `apiKey` → 直连；否则用 `proxyUrl`」。如果交付版预填了 `proxyUrl`，
   本机演示也会被拽去走 Worker；Worker 那边 Key 一失效，**本地线上一起废**。
   正确状态：本地留空（走直连），部署上线时再填回 Worker 地址。

### 0.3 部署上线（GitHub Pages，约 10 分钟）

1. **确认 Worker 是活的**（见 `worker/README.md`）：
   - 打 <https://dash.cloudflare.com/> → Workers & Pages → 选 `kanglu-ai`
   - **Settings → Variables and Secrets** 里 `DEEPSEEK_KEY` 必须是**有效**的 Key
     （换 Key 后一定要回来更新，否则前端一切正常、只是拿不到回答）
   - `ALLOW_ORIGINS` 填站点来源，例如
     `https://你的用户名.github.io,null`（`null` 是给本地 `file://` 用的）
2. **把站点放上网址**：在 GitHub 仓库里上传 `康鹭记忆-终版` 里的内容
   （或 push 到某个子目录），然后在仓库 **Settings → Pages** 打开，
   拿到形如 `https://用户名.github.io/仓库名/` 的地址。
3. **回填代理地址**：把 `康鹭记忆-终版/assets/js/ai-config.js` 的
   `proxyUrl` 改成 `'https://kanglu-ai.你的子域.workers.dev'`，重新上传这个文件。
4. **验证**：打开线上网址，点开小白鹭问一句；回答正常且**没有**"站内检索模式"
   字样 = 通了。若显示"站内检索模式"，按顺序查：
   ① Worker 的 `DEEPSEEK_KEY` 是否有效 ② `ALLOW_ORIGINS` 是否含你的站点来源
   ③ `proxyUrl` 是否填对（注意 `proxyPath` 默认 `/chat`）。

### 0.4 别忘了两件事

- **Key 一旦进过压缩包/聊天记录 = 已泄露**，请去 <https://platform.deepseek.com/>
  重新生成一把，旧的就地删除。新 Key 只写两个地方：本机 `_ai-config.local.js`
  和 Cloudflare Worker 的 `DEEPSEEK_KEY`。
- 在 DeepSeek 后台**设置消费上限**；Worker 的 `ALLOW_ORIGINS` **只能挡顺手盗用**
  （Origin 头可以被伪造），真要防滥用得再加按 IP 的限流（Cloudflare Rate Limiting）。

### 0.5 这台机器的两个环境坑（部署 AI 时踩过，务必先看）

**坑一：本机走代理才能访问 GitHub 与 workers.dev。**
系统代理是 `127.0.0.1:7890`，但 git 与 curl 默认不走它，于是：
`github.com:443` 与 `kanglu-ai.kanglu-memory.workers.dev:443` 直连全部超时。
**`api.deepseek.com` 反而直连可用**——所以"本地能直连大模型、线上却连不上代理"
曾被误判成 Worker 的 bug。正确姿势：

```powershell
# git 推送/拉取
git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 push origin main

# 命令行验证 Worker（Invoke-WebRequest / curl 都要带代理）
Invoke-WebRequest -Uri 'https://kanglu-ai.kanglu-memory.workers.dev/chat' -Method Post `
  -Proxy 'http://127.0.0.1:7890' -ContentType 'application/json' `
  -Body '{"messages":[{"role":"user","content":"hi"}]}' -Headers @{'Origin'='https://sunset-sunrise-sun.github.io'}
```
无头浏览器验证线上站点也要加 `--proxy-server=http://127.0.0.1:7890`。

**坑二：PowerShell 的管道会把 UTF-8 BOM 写进 Worker 的密钥。**
`echo 'sk-xxx' | wrangler secret put DEEPSEEK_KEY` 实测存进去的是
**36 个字符、首字符 U+FEFF**（正常 35 字符），DeepSeek 直接回 401，
而同一把 Key 直连 API 却是 200——极易误判成"Key 失效"。
**改用 node 喂 stdin**（`_putsecret.js` 的做法：`spawn('cmd', ['/c', wrangler, 'secret','put', 名字])`
然后 `child.stdin.write(key + '\n')`），写入前后用诊断端点核对
`len / head / tail / hasSpace / nonAscii` 再收工。

**这两个坑合起来的表现是"本地一切正常、线上永远退化成站内检索"**，
排查顺序建议：① 该 Key 直连 DeepSeek 是否 200 ② Worker 里密钥的**形态**
（长度 35、无 BOM、无空白）③ `ALLOW_ORIGINS` 是否含站点来源 ④ `proxyUrl` 是否已填。

### 0.6 `window.KL_AI` 不能再被两个配置共用（已修，别改回去）
`ai-config.js` 与 `ai-config.local.js` 都写 `window.KL_AI`。
旧写法是"先读公开配置存进 `pub`，再加载本地配置，最后 `Object.assign`"，
但**本地文件那一行 `window.KL_AI = {...}` 会把同一个全局整个替换掉**，
实测导致合并结果被丢弃、`proxyUrl` 变空、线上退化成站内检索。
现在的写法（`ai.js` 的 `loadConfig(src, into)`）：**每加载完一个文件就立刻把内容取走，
然后 `delete window.KL_AI`**，两个文件不再共享全局。改这块时务必保持这个模式。

## 一、三条环境铁律（违反会静默失败，很难查）

这一节是这份笔记里最值钱的部分。我在无头浏览器验证上浪费过好几轮，根因全在这里。

### 1. 不能用管道捕获浏览器进程的输出
**症状**：Edge 无头截图不出文件，连 exit code 都是空的，且**没有任何报错**。

**错误写法**（会静默失败）：
```powershell
& $edge --headless=new --screenshot="$out" "file:///..." 2>&1 | Select-String 'written'
```

**正确写法**：
```powershell
Start-Process -FilePath $edge -ArgumentList @(
  '--headless=new','--disable-gpu','--hide-scrollbars','--no-first-run','--no-default-browser-check',
  "--user-data-dir=$tmp",'--window-size=1440,1000','--virtual-time-budget=30000',
  "--screenshot=$out", "file:///C:/.../map.html"
) -Wait -NoNewWindow
```

原因：这个环境**不允许程序通过管道捕获输出**。把浏览器输出接进管道，它就静默不干活。
**教训**：验证工具失败时，先把 stderr 打开看，不要反复换参数。我曾用 `2>$null` 把唯一线索扔掉，空转好几轮。

### 2. `--dump-dom` 在本环境不可用
它依赖 stdout，同样被上面那条限制挡住。**要读页面状态，只能把数值渲染到页面上再截图读**：

```js
// 注入到页面里的探针
var pre = document.createElement('pre');
pre.style.cssText = 'position:fixed;left:0;top:0;z-index:99999;background:#000;color:#0f0;font:22px monospace;padding:12px';
pre.textContent = 'host = ' + Math.round(host.getBoundingClientRect().width) + ' x ' + ... ;
document.body.appendChild(pre);
```
然后截图，用眼睛读那行大字。**这个方法可靠，而且能读任意内部状态**。

### 3. 截图前要做的两件准备
- **`.reveal` 元素在无头截图里是透明的**：它们靠 IntersectionObserver 淡入，无头环境不触发。所以截图里出现的大片空白**通常不是 bug**，要在真浏览器里确认。
- **满屏封面（`100vh`）会把后面的内容全顶出截图**：想截第 2 屏之后，用临时副本注入 `.cover{display:none!important}` 再截。
- 临时副本（`_xxx.html`）**验证完要删掉**，别留在交付目录。

### PowerShell 另外两个小坑
- **不要把含 `--ink-3` 这种值的字符串直接写进 PS 命令**：`--` 会被当成自减运算符，整段脚本语法报错。复杂字符串替换一律**写成 .js 文件用 node 跑**。
- **不要用 `node -e "长脚本"`**：引号会被 PowerShell 吃掉，多次无输出。一律写脚本文件。
- **`[System.IO.File]::WriteAllText` 不认相对路径**，要用绝对路径（否则"假成功"）。
- `Get-Content` 默认按 GBK 解码 UTF-8 文件，**中文显示乱码是假象**，别据此判定文件坏了。

## 二、三维模块（scene3d.js）的三条硬约束

### 1. `PLACES` 里每个条目都必须有对应的三维网格
只往 `PLACES` 加"标签数据"会直接崩，页面显示：
```
三维街区初始化失败：Cannot read properties of undefined (reading 'name')
```
代码是先建网格、再按 id 取网格挂标签的；取到 undefined 就炸。**要新增地点，必须同时给它建模**（哪怕只是很简的形体）。

### 2. 地标必须留避让区，否则会被自建房贴脸埋掉
建筑生成会查询 `EXCLUDE`（矩形 `[x0,z0,x1,z1]`，通过 `inExclusion(x,z)` 生效）。
新增地标时**避让区要留得比形体大一圈**。真实教训：牌坊原本 6.2 单位高（约 2 层楼），
而楼房是 3–8 层（`FLOOR_H` 2.7–3.35，即 9–24 单位），牌坊在默认全景里**完全被埋掉、看不出来**。
后来把牌坊抬到 11.2 / 12.4（约 4 层）才立得住。

### 3. 取景观感取决于**容器宽高比**，不是尺寸 bug
同一套相机参数：
| 容器 | 比例 | 观感 |
|---|---|---|
| 760 × 561 | 1.35 : 1 | 楼群只占下缘一条，上方全是空地面 |
| 2560 × 900 | 2.84 : 1 | 楼群铺满，很漂亮 |

我为此误判过好几轮（怀疑过僵尸进程、尺寸未生效、时序）。最后**把地图页改成通栏**
（场景占满整屏宽 ≈ 2.26:1，侧栏内容移到场景下方横排）才彻底解决。
**结论**：给三维留容器时，**横向要够宽**；不要指望在窄高容器里也能好看。

## 三、跨模块调用的保护（必须做）

三维模块在迭代中改过 API 名字，我因此吃过一次**静默失效**：
`api.highlight` 当时不存在，抛了 `TypeError`，而**浏览器会吞掉事件处理里的异常**，
表现是"点按钮完全没反应，还不报错"。

所以本项目的规矩是：

```js
// 对三维模块的每一次调用都做存在性判断
if (api && typeof api.highlight === 'function') api.highlight(id);
if (api && typeof api.focusLandmark === 'function') api.focusLandmark(id);
```

并且**所有事件处理都包 try/catch 并把异常 console.warn 出来**（`map3d.js` 已这么做）。
`map3d.js` 的异常兜底还会把**真实错误显示在页面上**——这次定位"PLACES 缺网格"就是靠它，
比猜快得多。**这个兜底不要删。**

## 四、小白鹭（ai.js）的两处历史问题

1. **`var flipped` 被删导致头部不转**：`node --check` 只查语法，查不出这种运行时 ReferenceError。
   改完一定要在浏览器里真的动一下鼠标。
2. **对话窗会盖住右下角的小白鹭**：面板用 `top = Math.max(12, r.top - ph - 14)` 定位，
   只保证不超出屏幕顶部，**没保证不压到小鸟**；回答流式变长时面板向下长，越长越盖住它。
   已改为**底边锚定**（`top:auto; bottom: window.innerHeight - r.top + 14`），面板只会向上生长。

## 五、改完 JS 必须重新打包

所以源码是 ESM，交付用 esbuild 打成传统 script：

```powershell
cd C:\Users\28746\Desktop\人文数字-网站
node _build-final.js     # 产物：康鹭记忆-终版\assets\js\scene-bundle.js（约 794KB）
```

打包脚本里设了 `charset:'utf8'`，否则 esbuild 会把中文转成 `\uXXXX`，日后 grep 中文会全部搜不到。

## 六、内容诚实性的几条硬线（改内容时请守住）

- **三维是示意性重建，不是测绘成果** —— 页面已标明，别删这句话。
- **牌坊等位置是按公开地图与现场照片推断的相对关系**，不是实测坐标。
- **四份人物档案的配图一律标注"环境影像，非本人肖像"** —— 我们没拿到可公开的肖像授权，
  不要把画面里的路人指认为某位受访者。
- **缺影像的环节如实写"暂无现场影像"**，不要拿无关照片或生成图充数。
### 5. 小标题的「艺术字」：已换成**内嵌子集字体**（全平台一致）
用户要求把章标题换成图二那种毛笔书法字。最终做法（可复用到别处）：

- 字体选 **Ma Shan Zheng（马善政毛笔楷书）**，**SIL OFL 1.1** 授权 —— 明确允许网页嵌入与再分发。
- 原始字体 5.7MB，用 `pyftsubset` 按**本页标题用字**子集化：
  ```bash
  pip install --proxy http://127.0.0.1:7890 fonttools brotli      # 本机需走代理
  python -m fontTools.subset MaShanZheng-Regular.ttf \
      --text="<标题里出现的全部字符>" --flavor=woff2 --layout-features=* \
      --no-hinting --desubroutinize --output-file=brush-heading.woff2
  ```
  产物 **69KB / 189 字**（全站标题汉字 170 个，缺字检查 = 0）。
- 许可文件与来源说明随字体一起放在 `assets/fonts/`（OFL 要求），换字体记得同样处理。
- 作用范围：`.h-sec` / `.h-sub` / `.cm-txt` / `.chapter-inner h3` / `.wrap > h3`；
  **页首大标题（.page-banner h1 / .band-title）保持衬线** —— 它们压在影像带上，
  墨色渐变在深色底上会读不清。
- 外层挂朱红小印、**文字自己承载渐变**：`background-clip:text` 会把绘制裁剪到字形里，
  伪元素挂在同一元素上会被一起裁掉（实测印子完全不出现），所以印子挂在 h2/h3/.chapter-mark 上。
- `.h-sub` 的字体要写 `!important`：`style.css` 里 `.h-sub{font-family:var(--serif)}` 与本规则
  同权重，谁后加载谁生效，不钉死很容易被悄悄换回衬线。

**走过的弯路（别再重复）**：
1. 一开始想用本机商业字体（华文行楷 4MB、隶书、楷体），做成"装了就用、没装回落"——
   结果 **iPad / 多数移动端根本看不到**，等于没改。
2. 为判断本机有没有该字体，我尝试用 canvas/DOM 量字宽：**汉字在字体里一律占满一个字身**，
   量「康鹭地图」在任何字体下都是 12×48 = 576px，**完全区分不出字体**（八种字体全返回 576）。
   要判字体只能用拉丁字符（`STXingkai` 476.5 / `MS YaHei` 558.3 / `SimSun` 432），
   或者干脆像现在这样——内嵌字体，不判。
3. 用 `document.fonts.check()` + 宽度差判"子集里有没有这个字"也不可靠；
   判覆盖请**直接读字体 cmap**（`fontTools`，见 `_glyphcheck.py` 的做法）。

### 6. 首页占比条：加之前先满足两条
（这条硬规矩属于本节的「数字必须带范围与来源」）
- **数字必须带范围与来源**；来源不明的标「口径待核」。
  曾经有一张把定性描述画成比例的条形图（"日结工占主流 70%"），**已因无来源而删除**。
  后来**按来源补回了这一条**（《行业研习》李婷《废除劳务派遣制度？广州城中村的日结工怎么说》，
  2026-03，虎嗅转载：日结工占康鹭用工的 50%–60%，旺季突击订单时可能超过 70%）。
  注意补回来的前提是**找到了可指的来源**，而且标签直接写「50%–70%」把范围摆出来。
  以后再想加占比条，先满足两条：① 来源可指（写进出处行 + `data.js` 的 `REFS`）；
  ② 区间必须显示出来。区间条的做法：`index.html` 的 `BARS` 给 `v`（基准）与 `hi`（上限），
  `main.js` 的 `initBars()` 在实条右侧生成 `.bar-range`（斜纹 + 半透明），
  避免区间被读成一条确定的实线。
- **变迁记录每条要区分「已发生 / 规划·预期」**，存在争议的年份要标注。
- 首页的六个数字已下沉到「关于研究 · 统计口径」；首页只保留一行代表性数字。

## 七、排版三条规则（细节打磨阶段定下来的，改版时别推翻）

### 1. 图片必须与正文共用同一条左右边界
"图比正文窄一点、居中放"是**做错过的写法**（用户原话：「图片也对齐，左右两边留空一样多」）。
正确做法：
- `.figure-block` **不再单独内缩**（`width:100%; max-width:none; margin-inline:0`）；
- 图组和正文都放在同一个盒里（首页是 `.chapter-inner`，简介章是 `#intro .wrap`）；
- 想加呼吸感就**把整列一起收窄**：调 `.chapter-inner` / `#intro .wrap` 上的 `--col-pad`
  （`clamp(0px, 2vw, 28px)`，手机端为 0）。文字和图一起缩，边界才仍然重合。
- 另外注意 `#intro .wrap` 的 `max-width` 必须与 `.chapter-inner` 的 `1220px` **取同一个数**，
  否则窄屏下简介正文会和它下面那三张图错开（旧代码在 ≤1080px 时把它改成 `var(--maxw)`，已修掉）。

### 2. 工序链的箭头用真实 DOM 元素，不要用伪元素
`.chain` 是「6 列 + 5 个箭头格」共 11 个网格项（`grid-template-columns:1fr var(--arw) … 1fr`），
箭头是 `main.js` 的 `renderChain()` 生成的 `<div class="chain-arw">`。

**为什么不用 `::after`**：在这个页面里，`.chain-step::after` 的百分比偏移解析得和预期不一致
（实测 `left:100%` 会多算 4px、`background-size:100%` 只画出 32px 宽），
量了五六轮都对不准，最后换成真元素，一次就量到「箭头中线与图标圆心差 0」。

箭头**必须居中**：箭头格有 `--arw`（56px）宽，而 `::after` 里的箭头图形 140px 长，
所以 `background-position` 要用 **center**（用 left 会贴着左边那枚图标，
用户反馈"箭头不居中"）。取 center 后实测：箭头左端到左圆、右端到右圆**各 ≈55px，两侧相等**。

**教训**：几何对不齐时，先换成可以直接 `getBoundingClientRect()` 的写法，再谈调参。

工序名称与时间戳只来自 `data.js` 的 `CHAIN`；6 列下的块内字号是 15px（全局正文仍是 18px）。

### 3. 左侧小节导航：收起成细轴、悬停展开（别再改回常驻面板）
只出现在 `background.html`。原来的写法是**常驻 145px 面板**（`position:fixed; left:14px`），
它的注释写着"给页面让出装订线"，但实测**并没有真让开**：

| 视口宽 | 面板右缘 | 正文左缘 | 结果 |
|---|---|---|---|
| 1200 / 1280 | 159px | 30px | ★ 压住约 130px |
| 1366 | 159px | 73px | ★ 压住约 86px |
| 1440 | 159px | 110px | ★ 压住约 49px |
| 1600 以上 | 159px | 190px+ | ✓ |

用户报的就是这个（iPad 上"挡着内容"）。现在改成：
- **收起态**：一条 28px 的细轴（纸色淡底 + 圆点 + 进度轴），落在左侧空白里，**不压正文**
- **悬停 / 键盘 Tab（`:focus-within`）** 展开成 145px 面板，标签滑入
- 显示门槛从 1200px **提到 1320px**：因为 28px + `left:16px` = 44px，而 1280px 视口下正文左缘只有 30px，
  1200–1319 这一段轴也会压正文，所以整条隐藏
- **≤1319px 改用右下角「带路」按钮 + 弹出面板**（原来那条通栏的横排跳转条占掉一整屏高度，已删掉）

**两个坑记下来**：
1. **不要用 `transform:translateY(-50%)` 让 `position:fixed` 元素垂直居中**：
   父层一旦有 `transform`，它就成了 fixed 的包含块，`right:auto` 会被解析成
   "到包含块右边缘的距离"，展开时面板会从左边弹出去。这里改用 `margin-top:calc(高度 / -2)`。
2. **不要用「负边距 + 右对齐」把圆点挪到轴线上**：负边距会把圆点一起挤出容器、
   被 `overflow:hidden` 裁掉（像素扫描确认轴带里 0 个深色像素）。
   现在用 `grid-template-columns:22px 6px → 50px 95px`：圆点列 + 标签列，
   靠**列宽变化**让标签滑入，圆点始终留在轴线上。

### 4. 三维标针外面出现过一块白色圆角底板 —— 元凶是 `.map-stage svg`

**症状**：地图页里每枚水滴标针外面多一块 22×36 的纸白圆角方块，
看着就是"白色长方形上面放了个水滴"。

**怎么定位的**（别猜，一路量下去）：
1. 先读 `.k3d-label` 的 computed style —— 全部是 `background:rgba(0,0,0,0)`、
   `border:0`、`box-shadow:none`，**不是 button 的样式**；
2. 把截图放大 4 倍逐像素量，白块正好 22×36（= 标针 SVG 的 viewBox 尺寸），
   说明白底刷在 `<svg class="k3d-pin">` 自己身上；
3. 把标针的 `outerHTML` 与逐层 computed style 打到页面上读，
   看到 `<svg class="k3d-pin">` 的 `bg=rgb(241,235,221)`。

**根因**：`style.css` 里有一条过宽的规则
```css
.map-stage svg{ width:100%; height:auto; display:block; background:var(--paper); border-radius:2px; }
```
它本意只给左栏那张平面关系图（`#kangluMap2d`）铺垫底色，
但 `.map-stage` 里同时装着三维场景，**每枚标针也是 `<svg>`**，于是一起被刷白。
（首页那张三维大图没有这个问题，因为它是独立导出页渲染的，不带 `.map-stage`。）

**修法**：改成只作用于平面图 `#kangluMap2d, .map2d-host svg`，
并补一条 `.map-stage svg.k3d-pin{ background:none; border-radius:0 }` 兜底。
修后实测：`#kangluMap2d bg=rgb(241,235,221) radius=2px`（平面图底色仍在）、
`.k3d-pin bg=rgba(0,0,0,0) radius=0px`（标针纯水滴）。

**教训**：给"装了第三方内容（三维 / 画布 / 组件）"的容器写后代选择器时，
不要用 `容器 svg` / `容器 button` 这种泛型后代，一定带上具体类名或 id。
