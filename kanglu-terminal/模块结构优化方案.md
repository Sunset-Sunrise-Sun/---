# 康鹭记忆 · 模块结构优化方案

> 目标：**把三维街区做成全站亮点**，首页减负，模块之间的关系一句话能说清，且**尽量不丢现有内容**。

---

## 一、现在的问题（有据可查，不是感觉）

盘点 `康鹭记忆-终版` 现有模块：

| 页面 | 现有标题数 | 问题 |
|---|---|---|
| `index.html` | **13 个** | 首屏之后连着铺了 7 个内容块；**「人物档案」出现两次**（一次是入口卡、一次是轮播）；「数字里的康鹭」和「人口与产业构成」其实是同一件事拆成两个标题 |
| `background.html` | **16 个** | 内容最厚（产业逻辑、空间形态、编年、改造政策、现场材料、参考文献全挤在一页），读者要滚很久 |
| `map.html` | 3 个 | **三维街区被排在部门页第三位之后**，从导航看不出它是重点；原来的二维意象图现在没地方放了 |
| `people.html` | 2 个 | 相对健康 |
| `statement.html` | 6 个 | 相对健康 |

**核心症状**：① 首页平均用力，没有主角；② 亮点（三维）开场看不见；③ 长内容没有归口（编年/政策/空间 全在"背景资料"）。

---

## 二、优化后的结构：一条主线，六个归口

设计文件里写明的阅读逻辑是 **「看见街区 → 遇见具体的人 → 理解产业 → 看见变化」**。
把它当作全站骨架，导航按这条线排：

| # | 页面 | 一句话职责 | 主要内容来源（现有，不新造） |
|---|---|---|---|
| 1 | **走进康鹭**（index） | 30 秒看懂这是什么地方，并把人推向三维街区 | 封面 + 一句话 + **三维街区入口** + 四份人物 + 一组数字 + 变迁一瞥 + 研究入口 |
| 2 | **三维街区**（map） | **全站亮点**：可以走进去的街区 | 三维场景 + 地点档案卡片 + 空间关系速览 + 节点索引 + 规划图对照 + 三种读图方式 +（保留）二维关系图 |
| 3 | **人物档案**（people / person） | 让街区里的人开口 | 四份档案 + 单份详情（四段式） |
| 4 | **产业背景**（background，收窄） | 解释它靠什么运转 | 区位与概况、产业逻辑（含小单快反/为什么必须在这里/脆弱的一面）、空间形态、招工广场专节、乡土词条 |
| 5 | **变迁记录**（chronicle，新拆分） | 有日期的变化与政策 | **从 background 拆出**：编年、改造与政策（拆治兴/三步走）、产业转移清远方案、现场材料、参考文献 |
| 6 | **关于研究**（statement） | 方法与边界 | 现有五节不动 + 增补三维与 AI 的说明 |

**导航顺序**：走进康鹭 · **三维街区** · 人物档案 · 产业背景 · 变迁记录 · 关于研究

> 三维街区从第 4 位提到第 2 位 —— 这是"重点凸出"最直接的一步。

## 三、首页的新顺序（7 块 → 5 屏）

| 屏 | 内容 | 为什么这样排 |
|---|---|---|
| **1 首屏** | 深色封面（保留）＋主标题「在街巷之间，看见一座制衣村」＋一句话＋**两个按钮**：`走进三维街区` / `先看人物` | 首屏只回答三件事：这是哪、为什么值得看、从哪开始 |
| **2 街区入口** | **静态街区图**（三维场景导出一张斜俯视大图）＋ 一句"可以拖动旋转、点地标看记录"＋ `进入三维街区` 按钮 ＋ 三处地标的小缩略图（牌坊／牌坊／广场） | 不塞活的 3D（避免首页变慢、也避免与地图页重复），但把亮点用一张满幅图**立住** |
| **3 制衣的人** | 四份档案**编辑式直排**（照片／身份／一句原话／`读完整档案`） | 现有轮播要滑动才看得全 —— 改成直排，四份一次可见 |
| **4 一组数字** | 六个数字**分两组**（空间与人口 / 生产与更新），统一砖红，每项标 `范围 · 来源`，缺来源的标`口径待核`；**删掉那张"日结工占主流=70%"的条形图**（无来源） | 把"数字里的康鹭"和"人口与产业构成"合并成一块，去重 |
| **5 变迁一瞥 + 研究入口** | 三条有日期的关键节点（带`已发生/规划`标签）＋ `查看完整变迁记录`；页尾并列"研究方法 · 参考文献 · 影像与 AI 说明" | 长内容全部推到归口页，首页只留钩子 |

**删/并的三处**：① 首页那条重复的「人物档案」入口卡（并入第 3 屏）；②「数字里的康鹭 + 人口与产业构成」两块合一；③ 首页的「发展历程」整段移到 `chronicle.html`，首页只留 3 条钩子。

## 四、模块之间的关系

```
                    ┌─────────────────────────────┐
                    │  1 走进康鹭（首页）          │
                    │  封面 → 街区入口 → 人 → 数字 │
                    └───────┬─────────┬───────────┘
            点"进入三维街区" │         │ 点人物卡
                            ▼         ▼
        ┌───────────────────────┐  ┌──────────────────────┐
        │ 2 三维街区（亮点）     │  │ 3 人物档案 / 详情     │
        │  · 拖动/缩放/复位      │  │  · 四份直排           │
        │  · 点地标→卡片弹在位置 │  │  · 四段式详情         │
        │  · 空间关系/节点索引   │◄─┤  · 详情里可"在街区看" │
        │  · 规划图对照          │  └──────────────────────┘
        └───────┬───────────────┘
                │ 卡片里给"产业背景 / 人物 / 变迁"链接
                ▼
   ┌────────────────────┐   ┌────────────────────┐
   │ 4 产业背景（收窄） │   │ 5 变迁记录（拆分） │
   │  为什么聚在这里     │   │  有日期的变化+政策  │
   └─────────┬──────────┘   └─────────┬──────────┘
             └──────────┬─────────────┘
                        ▼
              ┌──────────────────────┐
              │ 6 关于研究（方法与边界）│  ← 全站页脚常驻入口
              └──────────────────────┘
```

**三条关系规则**（保证不散）：
1. **每个内容块只有一个"家"**（编年只住 `chronicle`，产业逻辑只住 `background`），别处只放钩子；
2. **三维是唯一能"走进空间"的地方**，所有涉及地点的地方（人物详情、产业步骤、变迁事件）都给一句"在三维街区里看"；
3. **一切可追溯信息（来源、口径、影像说明、AI 边界）只住 `statement`**，页脚常驻。

## 五、三维街区"亮点化"的具体做法

| 做法 | 说明 |
|---|---|
| 导航提到第 2 位 | 名字建议从「康鹭地图」改成 **「三维街区」**（"地图"让人以为是平面图） |
| 首页给满幅静态图 + 入口 | 用三维场景导出的斜俯视大图，配"可以拖动旋转"的说明 |
| 页内做成一屏一主 | 三维占满首屏；原来的**二维意象图**收进下方一栏「关系图（平面版）」，作为对照而不是并列 |
| 地点卡片弹在地标位置 | **已实现** ✓（点标签 → 卡片贴在该地标旁）|
| 牌坊要立得住 | 现楼高 9–24 单位，牌坊只有 6.2/8.6（约 2 层）→ 被埋。建议抬到 **11.2 / 12.4**（约 4 层）；街口清空区已存在，不用动 |
| 默认视角 | 保持现在的全景（三地标同时在画面内）；**不要**为了突出牌坊而拉近 —— 我实测拉近后取景会空掉 |
| 导览 | 「跟随小白鹭」逐站镜头已可用 ✓；后续可让小白鹭本体飞过去 |

## 七、建议的实施顺序（每步都能单独看效果）

1. **导航与页面骨架**：加 `chronicle.html`，导航改成六项、三维提到第二位（先空页占位，内容后搬）
2. **首页减负**：7 块 → 5 屏，去重"人物档案"、合并数字两块、发展历程只留钩子
3. **三维亮点化**：首页加满幅静态图 + 入口；`map` 页把二维图降级为对照栏；牌坊抬到 11.2/12.4
4. **内容搬迁**：编年/政策/现场材料 → `chronicle`；方法 → `statement`；参考文献 → `statement`
5. **全站实测**：桌面 + 手机、导航不溢出、三维交互、无控制台错误
6. **打包交付**

> 第 1、2 步做完，首页的"繁琐"就解决了；第 3 步做完，三维就是亮点。

## 九、参考站分析（bjjy.cn/bngj 北京公交百年）与对首页的修正

用户给了一个参考站。它的做法很值得借，**核心是"首页即章节目录"**：

**它的结构**
- 顶部导航是 4 个大栏目（车型谱／票证集／线站图／人物志），每个栏目下挂 2–3 个子页
- **首页是一条纵向的"章"**：每章 = 一个章节标记（logo1…logo5）＋ 一段 4–6 行短文字 ＋ **2–3 个大幅图片入口**（整块可点，直达子页）
- 结尾还有一个收束章（endlogo + 一段结语）
- 章节里偶尔内嵌操作提示（如"横向滑动浏览路线"），移动端另有专门切图（mob-*.png）

**它为什么"不繁琐"**：首页**不承载深度内容** —— 没有数字表格、没有时间轴、没有长段落，只有"章号 + 几句话 + 一张大图入口"。深度全在子页。

**它对康鹭的启示（不照搬）**
1. **首页改成 5 个"章"**，每章：`编号（01–05）` ＋ 一段 3–5 行短文字 ＋ **一块大幅视觉入口**（可整块点击）；
2. **入口以图为主**，不是现在那种"卡片 + 标题 + 摘要 + 按钮"的堆叠；康鹭有现成的田野照片可以直接当入口图；
3. **章号当骨架**（它用 logo1–5，我们用 01–05 ＋ 中文小节名），这与设计方案里的"章节编号构成档案感"一致；
4. **三维单独成章、并且是尺幅最大的一章**（参考站没有三维，这恰是康鹭能超出它的地方）—— 满幅静态街区图 ＋ `走进三维街区`；
5. **结尾章**用来收"研究方法与来源"（对应它那个 endlogo 收束章）。

**修正后的首页（替代第三节的旧版）**

| 章 | 内容 | 高度 |
|---|---|---|
| **01 走进康鹭** | 深色封面 ＋ 主标题 ＋ 一句话 ＋ 一个下滚提示 | 满屏 |
| **02 三维街区 ★** | 满幅静态街区大图（三维导出）＋ 一句"可以拖动旋转、点地标看记录"＋ `进入三维街区`；三地标小图在角上 | 满屏（**全站尺幅最大**） |
| **03 制衣的人** | 四份档案**以图为主**的入口（每份一张环境图 ＋ 一句原话），整块可点进档案 | 一屏放四块 |
| **04 产业与变迁** | 两个入口：`产业背景`（小单快反／招工广场）｜`变迁记录`（拆治兴／旧改） | 半屏 |
| **05 关于研究** | 方法与来源的收束章 ＋ 页脚入口 | 半屏 |

**和旧版方案的差别**：旧版第 4 屏还留着"六个数字分组"，现在按参考站的做法**把数字下沉**——放 `statement` 的"统计口径"一节，或放进 `产业背景`；首页只保留一到两个最有代表性的数字作为一句文案（例如"约 1.1 平方公里、近 2 万家厂与档口"），不再做大表格。这样首页从 7 块真正压到 5 章。

**注意不要照搬的地方**：参考站的入口文字是"烧进图片"的（cxyj-text.png 等），这不利于无障碍与检索；康鹭的入口图用照片，**标题文字用 HTML 叠在上面**，保留可选中、可被搜索引擎读到。
